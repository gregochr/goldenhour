### Added — admin editing of named areas and location aliases

The Operations tab's location management view gets an "Areas" section (create, rename, other names, a filterable member picker, delete with a confirm) and an "Also known as" field on the location edit form, so an admin can teach Ask "Hadrian's Wall" or "the Heugh" without a migration. Endpoints are ADMIN-only: `GET|POST /api/areas`, `PUT|DELETE /api/areas/{id}`, `PUT /api/areas/{id}/locations`, `GET /api/locations/aliases`, `PUT /api/locations/{id}/aliases`. A rename never touches an area's members, and a location's aliases are saved by their own request after the location itself, so saving a location can never rewrite them. Location names, location aliases, area names and area aliases are now one normalised namespace (`NameNamespaceGuard`): no two may be equal, an area name or alias may not sit inside a place's name or alias, and a place may not be renamed to hide a named area (clashes answer 409 for areas and aliases, and the existing 400 for a location add or rename). Also fixes `api-endpoints.md`, which documented `PUT /api/locations/{name}/reset-failures` where the code maps `/reset-failures` (`docs/engineering/ask-named-areas-plan.md`, A3).
