Registration
1. Untick marketing by default. It currently defaults to true. Under UK PECR/GDPR, marketing consent has to be an active opt-in, so this is the one change I'd treat as required.
2. Drop "Confirm email". The verification link already proves the address, so a typo is caught there and the user can resend.
3. Put email first. It's what people expect, and the username can then be pre-filled from the email if you want.
4. Say why the button is disabled. Create account stays greyed out until terms are ticked, with nothing on screen saying so.
5. Remove the second Turnstile on Set password. The emailed token already proves a real person.
6. Hint contrast. Hints use text-plex-text-muted (42% ink) at 12px, which is around or below 4.5:1 on the card. text-secondary is safer. The password checklist also uses Tailwind green-400; verdict-go would match the palette.
Sign in
1. No password reset. LoginPage has no forgot-password route. If there isn't one elsewhere, this is the biggest gap: a locked-out user can't recover their account.
2. Accept username or email. People forget usernames more often than emails. This needs a backend lookup, because login() takes a username today.
3. Session-expired message. It's centred amber text above a left-aligned lockup and card. Left-aligning it inside the card would read better.
4. After sign-in, the postcode prompt (frame 4) slots in here.
