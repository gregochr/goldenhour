ECLIPSE — rebuilt in v2's language

My first pass wasn't in keeping, and it's worth saying where it went wrong. It was built on the Coming up rail from the previous version — but v2 demoted that to a tab and gave the featured event a promoted strip at the top of Plan instead. It also introduced a loud red "rare" row, when v2 already has .ph .rare doing exactly that job quietly: "first coincidence since 2 Mar". And the accent was a bright Tailwind red dropped into a palette with no saturation like it anywhere.

Here it is again, using what's already there. An eclipse is an almanac event with a once-in-decades return period and a coincidence worth driving for — precisely what the promoted strip was built to carry.

◐Deep partial eclipse iWhy 94% still isn't duskBrightness falls with the uncovered area, not with how dark it feels. At maximum a sliver of photosphere is still throwing roughly a twentieth of full sunlight — thousands of times brighter than a full moon, and a meter still reads daylight. What changes is the quality: colour goes metallic, shadows sharpen to knife edges, and pinholes between leaves cast crescents on the ground. The clear to the west figure is the new work. Existing site data has elevation and aspect; this needs a horizon-obstruction test on a fixed bearing (WNW, 11°). Reusable for every low-sun event.

Reuses .ph .rare as-is. Add returnYears to almanac events so the string generates rather than being authored: eclipse 55, spring tide null.

Two calls for you.
  1. Promotion timing. The promoted strip currently shows tonight's coincidence. An eclipse at 19:13 needs the trip decided the evening before, so it wants to promote at T−1 — which is a rule change, not a content change.
  2. The west-horizon figure. "31 of 57 clear to the west" is the most useful number on the strip and the only one you can't compute today. If that's too much work for one event, the strip drops to coverage and timing and reads thinner than the snow and tide versions.
